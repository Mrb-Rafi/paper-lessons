Modern AI in 49 Papers · Lesson 5

ResNet,
from zero.

In 2015 four researchers at Microsoft Research noticed something strange: stacking more layers onto a good image network made it worse, even at fitting its own training images. Their fix was one line of arithmetic: let every pair of layers compute a correction to its input, and add the input back, \(y = F(x) + x\). With these “shortcut connections” they trained networks of 152 layers on ImageNet (and over 1,000 on CIFAR-10), won five competition tracks, and gave almost every later architecture, Transformers included, its backbone. This book starts from “what is a neuron?” and “what is a convolution?”, and ends with every equation, every architecture in Table 1, every experiment and every table of the paper and its appendix. You need no background: every idea comes with something to play with.

Based on Kaiming He, Xiangyu Zhang, Shaoqing Ren and Jian Sun, “Deep Residual Learning for Image Recognition”, CVPR 2016 (arXiv:1512.03385). Official models: KaimingHe/deep-residual-networks (Caffe, MIT licence); training-faithful reference code: torchvision v0.20.0, models/resnet.py. Foundations

Neurons, layers and depth

A deep network is a long chain of simple layers, and depth lets it describe complicated things cheaply.

A neuron takes a few numbers, multiplies each by a weight, adds them up with a bias, and bends the total with an activation function. ResNet uses the simplest bend there is, the ReLU (rectified linear unit): \(\sigma(z) = \max(z, 0)\), “keep positives, zero out negatives”. Try it:

Many neurons reading the same inputs form a layer. Stack layers, each reading the outputs of the one below, and you have a neural network; the layers in between are hidden layers, and a network with many of them is deep. The number of layers that have weights is the network’s depth: when the paper says “a 152-layer network”, it counts exactly those.

Why stack instead of making one very wide layer? Each layer can reuse what the layer below computed. Here each layer is just two ReLU neurons that fold a line in half; stacking them doubles the number of straight pieces every time:

∑ The math
\[ h_{l+1} = \sigma(W_l\, h_l + b_l), \qquad l = 0, 1, \dots, L-1, \qquad h_0 = x. \]

\(h_l\) is the list of numbers (a vector) coming out of layer \(l\); \(h_0 = x\) is the network’s input. \(W_l\) is the layer’s table of weights (a matrix, one row per neuron), \(b_l\) its biases, \(W_l h_l\) means “each neuron takes its weighted sum”, and \(\sigma\) applies ReLU to every entry. \(L\) is the depth. Tiny example: \(h = (1, 2)\), one neuron with weights \((0.5, -1)\), bias 0.5: \(0.5 - 2 + 0.5 = -1\), and \(\sigma(-1) = 0\).

📄 In the paper

The paper opens with depth: deep networks “integrate low/mid/high-level features and classifiers in an end-to-end multi-layer fashion, and the ‘levels’ of features can be enriched by the number of stacked layers (depth)”. In 2015 the best ImageNet networks had “a depth of sixteen to thirty” Paper §1. A footnote adds that whether stacked nonlinear layers can approximate any complicated function is “still an open question”, citing work on the number of linear pieces of deep networks (Montúfar et al., 2014) Paper §3.1, footnote 2. The folding widget above is in the spirit of that work.

Loss, SGD, momentum and weight decay

Training walks downhill on the loss, with a little momentum and a gentle pull towards small weights.

To classify an image into one of \(K\) classes, the last layer outputs \(K\) scores, and the softmax turns them into probabilities (exponentiate each score, divide by the total). The loss is the cross-entropy: minus the log of the probability given to the right class. All weights and biases together are the parameters.

The gradient says, for every parameter, how much the loss would rise if that parameter grew a little. Gradient descent steps every parameter against its gradient; the step size is the learning rate \(\eta\). Here it is on a one-parameter loss:

With a million training images, the exact gradient is too expensive for every step. Stochastic gradient descent (SGD) estimates it from a random minibatch of a few hundred images. The paper adds two standard refinements. Momentum keeps a running “velocity”, so steps that agree build up speed and steps that zig-zag cancel. Weight decay adds a small pull of every weight towards zero, which discourages needlessly large weights:

∑ The math
\[ v \leftarrow \mu\, v + \big(g + \lambda w\big), \qquad w \leftarrow w - \eta\, v. \]

\(w\) is one parameter, \(g\) its minibatch gradient, \(v\) its velocity (starting at 0), \(\mu\) the momentum, \(\lambda\) the weight decay and \(\eta\) the learning rate. The \(\lambda w\) term is the gradient of an extra loss \(\tfrac{\lambda}{2}w^2\). Worked step with the paper’s \(\mu = 0.9\), \(\lambda = 0.0001\), \(\eta = 0.1\): \(w = 2\), \(g = 0.5\), \(v = 1\): new \(v = 0.9 + 0.5 + 0.0002 = 1.4002\); new \(w = 2 - 0.14002 = 1.85998\).

📄 In the paper

ImageNet: “SGD with a mini-batch size of 256. The learning rate starts from 0.1 and is divided by 10 when the error plateaus … We use a weight decay of 0.0001 and a momentum of 0.9” Paper §3.4. CIFAR-10: the same weight decay and momentum, mini-batch 128 §4.2.

⌨ In the code

The authors’ README warns that their Caffe SGD uses exactly the form above, \(v := \mu v + \eta g\) (the learning rate inside the velocity; equivalent while \(\eta\) is constant), and that libraries using \(v := \mu v + (1-\mu)\eta g\) change the effective learning rate. This book’s toys use the collection’s NN.SGD (nn.js), the form shown above, with weight decay added to the gradient in rn.js (trainer).

Foundations

Backpropagation through a deep stack

The gradient reaching a low layer is a product of one factor per layer above it, so it can shrink or blow up with depth.

The loss is computed in many small steps. The chain rule says how a small change at the bottom affects the loss at the top: multiply the local slopes of every step in between. Doing this from the loss downwards through every layer is backpropagation. When a value is used in several places, the gradients arriving from each place are added; this sum rule will matter for shortcuts.

Multiplying many numbers is risky. If the typical factor is a bit below 1, the product shrinks towards zero: a vanishing gradient, and the lowest layers barely learn. A bit above 1, it explodes: an exploding gradient.

∑ The math
\[ \frac{\partial \ell}{\partial h_l} = \frac{\partial \ell}{\partial h_L}\;\frac{\partial h_L}{\partial h_{L-1}}\cdots\frac{\partial h_{l+1}}{\partial h_l} = \frac{\partial \ell}{\partial h_L}\prod_{i=l}^{L-1}\frac{\partial h_{i+1}}{\partial h_i}. \]

\(\ell\) is the loss, \(h_i\) the output of layer \(i\), and \(\partial h_{i+1}/\partial h_i\) the local slope of layer \(i+1\) (for vectors, a matrix of slopes, the Jacobian). \(\prod\) means “multiply together”. With scalar factors all equal to 0.9 and 50 layers, the product is \(0.9^{50} \approx 0.005\); with 1.1, it is \(1.1^{50} \approx 117\).

📄 In the paper

“An obstacle to answering this question was the notorious problem of vanishing/exploding gradients, which hamper convergence from the beginning. This problem, however, has been largely addressed by normalized initialization and intermediate normalization layers” Paper §1, citing Hochreiter (1991), Bengio et al. (1994) and Glorot & Bengio (2010). Chapters 5 and 6 cover the two fixes; Chapter 16 shows that the paper’s problem is a different one.

Training error, test error and overfitting

A network is judged on images it has never seen; comparing its errors on training and test images tells you what went wrong.

Here is a whole small network learning, with backpropagation and gradient steps doing the work:

Data come in separate sets. The network learns from the training set; we measure it on a test set (or a validation set) of examples it never trained on. The fraction misclassified is the error. Two failure modes look different in these two numbers. Underfitting: the model cannot even fit the training data; both errors are high. Overfitting: the model fits the training data, noise included, and does worse on new data; training error is low, test error high.

💡 Intuition

More flexibility can only lower the training error when the optimizer does its job: a more flexible model can always imitate a less flexible one. Keep this in mind. The surprise of the ResNet paper is a case where adding layers raised the training error.

📄 In the paper

ImageNet models are trained on 1.28 million images and evaluated on 50,000 validation images, plus 100,000 test images scored by the competition server; CIFAR-10 has 50,000 training and 10,000 test images Paper §4.1, §4.2. The paper’s key distinction: degradation “is not caused by overfitting, and adding more layers to a suitably deep model leads to higher training error” §1.

Foundations

Initialization: keeping signals alive

Random starting weights must have just the right spread, or the signal dies or explodes before it reaches the top.

Before training, weights are set to small random numbers. Their spread matters enormously in a deep network: each layer multiplies the size of the signal by roughly the same factor, so 50 layers multiply it by that factor to the 50th power, just like gradients in Chapter 3. He initialization (He, Zhang, Ren & Sun, 2015, the same authors) picks the spread so that, with ReLU, the factor is exactly 1 on average:

∑ The math
\[ w \sim \mathcal{N}\!\left(0,\ \frac{2}{n}\right), \qquad n = k^2\, C_{\text{in}} \ \text{for a } k\times k \text{ convolution}. \]

\(\mathcal{N}(0, s^2)\) means “random, bell-shaped, centred at 0 with spread (standard deviation) \(s\)”. \(n\) is the number of inputs each neuron sums (its fan-in). Why 2? A weighted sum of \(n\) inputs with weights of variance \(2/n\) has variance about \(2\times\) the average squared input, and ReLU zeroes half of it, giving back a factor of 1. The older Xavier/Glorot rule uses \(1/n\), which halves the variance at every ReLU layer: after 50 layers, the size shrinks by \(2^{-25} \approx 3\times10^{-8}\).

📄 In the paper

“We initialize the weights as in [12] and train all plain/residual nets from scratch” Paper §3.4; [12] is He et al., “Delving deep into rectifiers” (ICCV 2015), the source of the \(2/n\) rule. The CIFAR-10 nets use the same §4.2.

⌨ In the code

torchvision: nn.init.kaiming_normal_(m.weight, mode="fan_out", nonlinearity="relu") for every convolution (resnet.py L208–213). It uses the fan-out \(k^2 C_{\text{out}}\), which keeps the backward gradients’ size constant instead of the forward signal’s; inside a stage, where \(C_{\text{in}} = C_{\text{out}}\), the two are the same. This book’s heParam in rn.js uses the fan-in.

Foundations

Batch normalization in one chapter

Re-centre and rescale every channel using the current minibatch, then let the network re-stretch it as it likes.

Batch normalization (BN; Ioffe & Szegedy, 2015, lesson 4) is a layer that takes each channel’s values across the minibatch, subtracts their mean and divides by their standard deviation, so they have mean 0 and spread 1, and then multiplies by a learned scale \(\gamma\) and adds a learned shift \(\beta\). Whatever the layer below does to the scale of its outputs, the next layer sees a well-behaved range:

∑ The math (BN paper, Algorithm 1)
\[ \mu = \frac{1}{m}\sum_{i=1}^m x_i,\quad \sigma^2 = \frac1m\sum_{i=1}^m (x_i-\mu)^2,\quad \widehat{x}_i = \frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}},\quad y_i = \gamma\,\widehat{x}_i + \beta. \]

\(x_1 \dots x_m\) are one channel’s values over the minibatch (for a convolution, over all images and all positions), \(\mu\) and \(\sigma^2\) their mean and variance, \(\epsilon\) a tiny constant (\(10^{-5}\)) to avoid dividing by zero. Worked example: values \(1, 3\): \(\mu = 2\), \(\sigma^2 = 1\), \(\widehat x = (-1, 1)\); with \(\gamma = 2, \beta = 0.5\): \(y = (-1.5, 2.5)\). At test time, \(\mu\) and \(\sigma^2\) are replaced by fixed averages computed on training data.

📄 In the paper

“We adopt batch normalization (BN) right after each convolution and before activation” Paper §3.4, and “we do not use dropout, following the practice in [16]” (the BN paper). The paper credits BN for removing the vanishing-gradient obstacle: its plain networks “are trained with BN, which ensures forward propagated signals to have non-zero variances” §4.1.

⌨ In the code

In the official Caffe models each convolution is followed by a BatchNorm layer (with use_global_stats: true, the stored statistics) and a Scale layer holding \(\gamma\) and \(\beta\) (ResNet-50-deploy.prototxt L20–37). The README notes the stored mean and variance were computed “using average (not moving average) on a sufficiently large training batch after the training procedure”. Our toy CNNs do the same (CNN.freeze in rn.js); our fully-connected toys use the shared NN.batchNorm.

Seeing with convolutions

Images are grids of numbers

A picture is a height × width grid of brightness values, one grid per colour channel.

A computer stores a grey picture as a grid of pixels, each a number for its brightness. A colour picture stores three grids, one per channel (red, green, blue). So a picture is a block of numbers of size height × width × channels. Inside a network, layers produce more such blocks, each with many channels; a single channel’s grid is called a feature map.

The paper’s two datasets: ImageNet (the 2012 classification challenge, ILSVRC): 1.28 million training photos in 1,000 classes, fed to the network as 224 × 224 × 3 crops. CIFAR-10: 60,000 tiny 32 × 32 × 3 photos in 10 classes (airplane, car, bird, cat, …). Our toy uses 8 × 8 × 1 pictures of digits.

∑ The math

An image is a 3-way table \(x[c, i, j]\): channel \(c\), row \(i\), column \(j\). Sizes: ImageNet crop \(3 \times 224 \times 224 = 150{,}528\) numbers; CIFAR-10 \(3 \times 32 \times 32 = 3{,}072\); our toy \(1 \times 8 \times 8 = 64\). Before training, the paper subtracts the per-pixel mean: the average image over the training set, so that inputs are centred around zero.

📄 In the paper

ImageNet: “A 224×224 crop is randomly sampled from an image or its horizontal flip, with the per-pixel mean subtracted” Paper §3.4. CIFAR-10: “The network inputs are 32×32 images, with the per-pixel mean subtracted” §4.2.

Seeing with convolutions

The convolution: a sliding kernel

A convolution slides one small table of weights over the whole picture, computing the same weighted sum at every position.

A fully-connected layer would give every pixel its own weight for every neuron: for a 224 × 224 × 3 input and just 64 neurons, almost 10 million weights, and no idea that an edge is an edge wherever it appears. A convolutional layer instead uses a small kernel (or filter), say 3 × 3, and slides it across the picture. At each position it multiplies the 9 pixels under the window by the 9 weights and adds them up. The same 9 weights are reused everywhere (weight sharing), so the layer finds the same pattern at every location.

∑ The math
\[ y[i, j] = b + \sum_{a=0}^{k-1}\sum_{b'=0}^{k-1} w[a, b']\; x[i + a,\ j + b']. \]

\(x\) is the input grid, \(w\) the \(k \times k\) kernel, \(b\) a bias, and \(y[i, j]\) the output at row \(i\), column \(j\). (Deep-learning libraries call this “convolution” although mathematicians would call it cross-correlation; the kernel is not flipped.) Worked example: kernel \(\begin{smallmatrix}-1&0&1\end{smallmatrix}\) on the three pixels \(0, 1, 1\): \(-0 + 0 + 1 = 1\): the left-to-right brightness increase. With a 3 × 3 kernel and no padding, an \(8 \times 8\) input gives a \(6 \times 6\) output.

📄 In the paper

“The convolutional layers mostly have 3×3 filters” Paper §3.3, the philosophy of VGG nets (Simonyan & Zisserman, 2015). Only the very first layer of the ImageNet networks uses a larger 7 × 7 kernel (Table 1). ResNet’s convolutions have no bias (bias_term: false in the Caffe files), because the BN that follows has its own shift \(\beta\).

⌨ In the code

torchvision builds every 3×3 layer with conv3x3: nn.Conv2d(in_planes, out_planes, kernel_size=3, stride=stride, padding=dilation, …, bias=False) (resnet.py L40–51). This book’s convolution is RNT.conv in rn.js, with its own backward pass, checked against finite differences.

Seeing with convolutions

Stride, padding and output size

Padding keeps the map size; a stride of 2 halves it.

Two knobs control the output size. Padding \(p\) adds a border of zeros around the input so the kernel can sit on edge pixels too; with a 3×3 kernel, padding 1 keeps the size unchanged. Stride \(s\) moves the kernel \(s\) pixels at a time instead of 1; stride 2 skips every other position and halves the map. ResNet downsamples (shrinks maps) with stride-2 convolutions:

∑ The math
\[ n_{\text{out}} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1. \]

\(n\) is the input size (height or width), \(k\) the kernel size, \(p\) the padding, \(s\) the stride, and \(\lfloor\cdot\rfloor\) rounds down. ResNet’s first layer: \(n = 224, k = 7, p = 3, s = 2\): \(\lfloor 223/2 \rfloor + 1 = 112\). A 3×3, stride 2, padding 1 on 56: \(\lfloor 55/2\rfloor + 1 = 28\).

📄 In the paper

“We perform downsampling directly by convolutional layers that have a stride of 2” Paper §3.3. In Table 1: conv1 is “7×7, 64, stride 2” (output 112×112), followed by a “3×3 max pool, stride 2” (56×56); “Downsampling is performed by conv3_1, conv4_1, and conv5_1 with a stride of 2” (28, 14, 7).

Seeing with convolutions

Channels, filter banks and cost

Each filter looks through all input channels at once, and a layer has many filters; that fixes its weights and its work.

Real layers read many channels and write many channels. Each of the \(C_{\text{out}}\) filters is a little block of \(k \times k \times C_{\text{in}}\) weights: it looks at the same window in every input channel and sums everything into one output number. So the output has \(C_{\text{out}}\) channels. Cost is counted in FLOPs, which in this paper means multiply-adds (one multiplication plus one addition).

∑ The math
\[ \text{weights} = k^2\, C_{\text{in}}\, C_{\text{out}}, \qquad \text{multiply-adds} = H_{\text{out}}\, W_{\text{out}}\; k^2\, C_{\text{in}}\, C_{\text{out}}. \]

\(H_{\text{out}}, W_{\text{out}}\) are the output map’s height and width. Example (conv2_x of ResNet-34): \(k = 3\), 64 → 64 channels, 56×56 output: \(9 \cdot 64 \cdot 64 = 36{,}864\) weights and \(56^2 \cdot 36{,}864 \approx 115.6\) million multiply-adds. Halve the map to 28 and double both channel counts to 128: weights ×4, positions ÷4: the work is the same 115.6 million.

📄 In the paper

The two VGG-style design rules: “(i) for the same output feature map size, the layers have the same number of filters; and (ii) if the feature map size is halved, the number of filters is doubled so as to preserve the time complexity per layer” Paper §3.3. FLOPs are “multiply-adds” §3.3.

Seeing with convolutions

1×1 convolutions

A 1×1 convolution looks at one pixel at a time and only mixes channels: a cheap way to change their number.

With \(k = 1\) a convolution sees no neighbours. At each pixel it takes the \(C_{\text{in}}\) channel values and computes \(C_{\text{out}}\) weighted sums of them: a small fully-connected layer applied at every pixel. That makes it the cheapest way to change the number of channels, either down (“reduce”) or up (“restore”). ResNet uses it twice: in the bottleneck block (Chapter 26) and in projection shortcuts (Chapter 22).

∑ The math
\[ y[o, i, j] = \sum_{c=1}^{C_{\text{in}}} W[o, c]\; x[c, i, j], \qquad \text{weights} = C_{\text{in}}\, C_{\text{out}}. \]

\(o\) indexes output channels, \(c\) input channels. Reducing 256 channels to 64: \(256 \times 64 = 16{,}384\) weights, against \(9 \times 256 \times 64 = 147{,}456\) for a 3×3.

📄 In the paper

Projection shortcuts are “done by 1×1 convolutions” Paper §3.3; in the bottleneck, “the 1×1 layers are responsible for reducing and then increasing (restoring) dimensions” §4.1.

⌨ In the code

torchvision’s conv1x1: nn.Conv2d(in_planes, out_planes, kernel_size=1, stride=stride, bias=False) (resnet.py L54–56).

Seeing with convolutions

Pooling

Pooling summarizes each neighbourhood by its maximum or average; global average pooling summarizes a whole map in one number.

Max pooling slides a window like a convolution but outputs the largest value in it; average pooling outputs the mean. Neither has weights. Global average pooling averages an entire feature map, so a block of \(C \times H \times W\) becomes just \(C\) numbers, one per channel, ready for a final fully-connected layer.

∑ The math
\[ \text{max pool: } y[i,j] = \max_{(a,b)\in \text{window}(i,j)} x[a,b], \qquad \text{global average: } g_c = \frac{1}{HW}\sum_{i,j} x[c, i, j]. \]

The output size follows the same formula as a convolution. ResNet’s max pool: \(k = 3, s = 2, p = 1\) on 112: \(\lfloor 111/2 \rfloor + 1 = 56\). Global average pool on ResNet-50’s last block: \(2048 \times 7 \times 7 \to 2048\) numbers.

📄 In the paper

“The network ends with a global average pooling layer and a 1000-way fully-connected layer with softmax” Paper §3.3; Table 1 lists a “3×3 max pool, stride 2” after conv1. VGG-19 instead uses five 2×2 max pools and three huge fully-connected layers (Fig. 3, left).

⌨ In the code

torchvision: nn.MaxPool2d(kernel_size=3, stride=2, padding=1) and nn.AdaptiveAvgPool2d((1, 1)) (resnet.py L200–206); the Caffe file’s pool5 is a 7×7 average pool (ResNet-50-deploy.prototxt L2293–2302).

Seeing with convolutions

Receptive field

Each layer sees a slightly bigger patch of the picture than the one below it; depth and stride make it grow.

One 3×3 layer sees a 3×3 patch. A second 3×3 layer on top sees 3×3 outputs of the first, which together cover 5×5 input pixels. The patch of input that can influence one output is its receptive field. Stacking small kernels grows it slowly; a stride of 2 makes every later layer grow it twice as fast.

∑ The math
\[ r_L = 1 + \sum_{l=1}^{L} (k_l - 1)\prod_{i<l} s_i. \]

\(r_L\) is the receptive-field width after \(L\) layers, \(k_l\) and \(s_l\) the kernel size and stride of layer \(l\). Two 3×3 stride-1 layers: \(1 + 2 + 2 = 5\). Three: 7, the same as one 7×7 layer, with \(3 \cdot 9 = 27\) instead of 49 weights per channel pair, and three ReLUs instead of one: the VGG argument for 3×3 kernels.

💡 Intuition

To recognize a dog, some unit must see the whole dog. Very deep networks of small kernels get there gradually, building strokes into parts and parts into objects. That is one reason depth matters for vision, and why the paper wants to go deeper without paying the price it is about to discover.

A whole convolutional network

Stages of 3×3 convolutions shrink the maps and widen the channels, then global pooling and one layer give the class.

A convolutional neural network (CNN) for classification chains everything so far: convolutions (each followed by BN and ReLU), downsampling, global average pooling and a final fully-connected layer with softmax. Groups of layers working on the same map size are stages. Here is a small one from this book’s toy, trained right now on noisy 8×8 digits; look inside:

The bigger question for the paper is cost. In 2014 the best “very deep” networks were the VGG nets, 16 and 19 layers of 3×3 convolutions. The paper’s 34-layer network follows VGG’s design rules but starts shrinking the maps right away and drops VGG’s giant fully-connected layers:

∑ The math
\[ \text{FLOPs} = \sum_{\text{layers}} H_{\text{out}} W_{\text{out}}\, k^2\, C_{\text{in}}\, C_{\text{out}} \;+\; \sum_{\text{fc}} d_{\text{in}}\, d_{\text{out}}. \]

This book’s count over the layers of Fig. 3 gives 19.63 G for VGG-19 and 3.64 G for the 34-layer plain net; the paper reports 19.6 and 3.6 billion. Parameters: VGG-19 has about 144 million, mostly in its first fully-connected layer (\(7 \cdot 7 \cdot 512 \times 4096 \approx 103\) million); the 34-layer net about 21.6 million.

📄 In the paper

“Our model has fewer filters and lower complexity than VGG nets. Our 34-layer baseline has 3.6 billion FLOPs (multiply-adds), which is only 18% of VGG-19 (19.6 billion FLOPs)” Paper §3.3. The 152-layer ResNet (11.3 G) is still cheaper than VGG-16 and VGG-19 (15.3 / 19.6 G) §4.1.

Is deeper always better?

Past a certain depth, adding layers to a plain network makes it worse, even on its own training data.

The paper asks a simple question: “Is learning better networks as easy as stacking more layers?” With He initialization and batch normalization, networks of tens of layers now start learning at all. So stack more and see. On CIFAR-10, a 56-layer plain network ends up worse than a 20-layer one:

“When deeper networks are able to start converging, a degradation problem has been exposed: with the network depth increasing, accuracy gets saturated (which might be unsurprising) and then degrades rapidly. Unexpectedly, such degradation is not caused by overfitting, and adding more layers to a suitably deep model leads to higher training error” Paper §1, Fig. 1. The same is seen on ImageNet (Fig. 4, Chapter 31) and, as the paper notes, on MNIST in the highway-networks paper §4.2.

⚠ Toy versus paper

In the paper the effect appears between 20 and 56 convolutional layers on CIFAR-10. In our tiny spiral toy (16 units wide, 1,500 steps) it appears between about 20 and 30 layers, and grows sharply by 50. The depth at which it bites depends on the task, the width and the training budget; the shape of the phenomenon is what carries over.

The degradation problem

Not overfitting, not vanishing gradients

The deep plain network fits its training data worse and its gradients are healthy: something else makes it hard to optimize.

Two familiar culprits come to mind, and the paper rules out both. Overfitting would show low training error and high test error; here training error is higher. Vanishing gradients would show tiny gradients in the lower layers; but with BN, the paper checked, both the forward signals and the backward gradients have healthy sizes. Check both in the toy:

📄 In the paper

“We argue that this optimization difficulty is unlikely to be caused by vanishing gradients. These plain networks are trained with BN, which ensures forward propagated signals to have non-zero variances. We also verify that the backward propagated gradients exhibit healthy norms with BN. So neither forward nor backward signals vanish.” The 34-layer plain net still reaches competitive accuracy, “suggesting that the solver works to some extent”. The authors “conjecture that the deep plain nets may have exponentially low convergence rates”, and leave the reason “to be studied in the future” Paper §4.1. Footnote 3: with 3× more training iterations the degradation is still there, “suggesting that this problem cannot be feasibly addressed by simply using more iterations”.

⚠ An open question

The paper does not explain why plain networks degrade; it offers a conjecture (very slow convergence) and a remedy. Later work has proposed explanations (for example, that gradients in deep plain networks become increasingly noise-like and uncorrelated across inputs, the “shattered gradients” of Balduzzi et al., 2017), but this book will not pretend the paper settled the question.

The degradation problem

The constructed solution

A deeper network can always copy a shallower one and do nothing in its extra layers, so it should never be worse.

Here is the paper’s thought experiment. Take a trained shallow network. Build a deeper one by copying its layers and inserting extra layers that compute the identity mapping: output = input, “do nothing”. The deeper network makes exactly the same predictions. So a deep solution at least as good as the shallow one exists. If training finds something worse, the fault lies with the optimizer, not with the network’s abilities.

∑ The math
\[ h \ge 0 \;\Rightarrow\; \sigma(I\,h + 0) = \max(h, 0) = h. \]

\(I\) is the identity matrix (1s on the diagonal, 0 elsewhere), so \(Ih = h\). Outputs of a ReLU layer are never negative, so a following layer with weights \(I\), zero bias and ReLU passes them through unchanged. That is how the widget inserts 24 “do-nothing” layers exactly; their batch normalization, at test time a fixed multiply-and-add, is set to multiply by 1 and add 0.

💡 Intuition

The identity is a very particular setting of the weights: exact 1s on the diagonal and exact 0s everywhere else. Starting from small random weights, nothing pulls a plain layer towards it. Gradient descent would have to discover the identity, layer after layer, by itself. The next part asks: what if “do nothing” were the easy default instead?

📄 In the paper

“There exists a solution by construction to the deeper model: the added layers are identity mapping, and the other layers are copied from the learned shallower model. The existence of this constructed solution indicates that a deeper model should produce no higher training error than its shallower counterpart. But experiments show that our current solvers on hand are unable to find solutions that are comparably good or better than the constructed solution (or unable to do so in feasible time)” Paper §1. In §4.1: “the solution space of the 18-layer plain network is a subspace of that of the 34-layer one”.

Residual learning

The big idea: learn the residual

Instead of asking a few layers to compute H(x), ask them to compute the change H(x) − x, and add x back.

Call \(H(x)\) the function some stack of layers ought to compute: the underlying mapping. The paper rewrites it as the input plus a correction. Let the layers learn the residual function \(F(x) = H(x) - x\), and recover the full answer by adding the input back: \(F(x) + x\). Nothing about what the network can represent changes; what changes is the default. With all weights at zero, a plain stack outputs zero, while a residual stack outputs its input.

∑ The math (paper §1, §3.1)
\[ F(x) := H(x) - x \quad\Longleftrightarrow\quad H(x) = F(x) + x. \]

\(x\) is the input to the stack (a vector, or a block of feature maps), \(H(x)\) the desired output, \(F(x)\) what the stacked layers actually learn, and \(:=\) means “is defined as”. This needs input and output of the same size (Chapter 22 handles the other case). Example: if \(H(x) = 1.1x\), then \(F(x) = 0.1x\): the layers only have to learn a 10% adjustment.

📄 In the paper

“Instead of hoping each few stacked layers directly fit a desired underlying mapping, we explicitly let these layers fit a residual mapping … We hypothesize that it is easier to optimize the residual mapping than to optimize the original, unreferenced mapping. To the extreme, if an identity mapping were optimal, it would be easier to push the residual to zero than to fit an identity mapping by a stack of nonlinear layers” Paper §1. §3.1 adds: “Although both forms should be able to asymptotically approximate the desired functions (as hypothesized), the ease of learning might be different.”

Residual learning

Zero is easier than identity

If the best layer is close to doing nothing, a residual layer only has to learn a small correction.

Chapter 17 suggested that solvers struggle to make a stack of nonlinear layers compute the identity. The residual reformulation makes the identity free: weights near zero. Watch the same stacks of layers learn a mapping that is the identity plus a small change:

The paper is careful about what it claims. Identity mappings are unlikely to be exactly optimal in real networks. But if the best function is closer to the identity than to the zero function, then finding a small perturbation of the identity should be easier than learning the function from scratch. The paper calls this preconditioning: reshaping a problem so the solver starts closer to the answer.

📄 In the paper

“The degradation problem suggests that the solvers might have difficulties in approximating identity mappings by multiple nonlinear layers. With the residual learning reformulation, if identity mappings are optimal, the solvers may simply drive the weights of the multiple nonlinear layers toward zero to approach identity mappings. In real cases, it is unlikely that identity mappings are optimal, but our reformulation may help to precondition the problem. If the optimal function is closer to an identity mapping than to a zero mapping, it should be easier for the solver to find the perturbations with reference to an identity mapping” Paper §3.1. The evidence for “closer to identity”: the small responses of Fig. 7 (Chapter 36).

⌨ In the code

torchvision takes the idea to its limit with an option the paper does not use: zero_init_residual=True sets the last BN’s \(\gamma\) in every residual branch to 0, so each block starts as an exact identity (resnet.py L215–224; its comment credits Goyal et al., 2017, with a 0.2–0.3% gain).

Residual learning

The building block, Eq. (1)

Two weight layers with a ReLU between them, plus a shortcut that adds the input to their output, then a ReLU.

The paper turns the idea into a building block (Fig. 2): weight layer → ReLU → weight layer, and a shortcut connection that skips both and carries \(x\) to the end, where it is added element-wise (entry by entry) to the layers’ output. The second ReLU comes after the addition. Step a number through it:

∑ The math (paper Eq. 1, §3.2)
\[ y = \mathcal{F}(x, \{W_i\}) + x, \qquad \mathcal{F} = W_2\,\sigma(W_1 x), \qquad \text{block output } \sigma(y). \qquad\text{(1)} \]

\(x\) and \(y\) are the block’s input and the sum before the last ReLU, \(\{W_i\}\) the block’s weights (here \(W_1, W_2\)), \(\sigma\) the ReLU; biases are left out “for simplifying notations” (and with BN there are none). In ResNet each “weight layer” is a 3×3 convolution followed by BN, and the addition is done “on two feature maps, channel by channel”. The shortcut has no weights and costs one addition per number.

📄 In the paper

“The operation \(\mathcal{F} + x\) is performed by a shortcut connection and element-wise addition. We adopt the second nonlinearity after the addition.” And: “The shortcut connections in Eqn.(1) introduce neither extra parameter nor computation complexity”, so plain and residual nets can be compared fairly “with the same number of parameters, depth, width, and computational cost (except for the negligible element-wise addition)” Paper §3.2, Fig. 2. “If \(\mathcal{F}\) has only a single layer, Eqn.(1) is similar to a linear layer: \(y = W_1x + x\), for which we have not observed advantages.” Experiments use \(\mathcal{F}\) with two or three layers.

⌨ In the code

torchvision’s BasicBlock.forward (resnet.py L89–105): identity = x; conv1 → bn1 → relu; conv2 → bn2; out += identity; relu. In the Caffe files, the addition is an Eltwise layer (default operation: sum), e.g. res2a (ResNet-50-deploy.prototxt L210–224), followed by res2a_relu.

Residual learning

Gradients through shortcuts

A shortcut adds an identity term to every block’s slope, giving the gradient a road that never narrows.

By the sum rule of Chapter 3, a block that outputs \(x + F(x)\) passes back the gradient through two routes: straight through the shortcut, and through \(F\). So each block’s local slope is “identity plus something”, instead of just “something”. Measure it on real networks, freshly initialized and without batch normalization:

∑ The math (this book’s derivation)
\[ \frac{\partial y}{\partial x} = I + \frac{\partial F}{\partial x}, \qquad \text{plain: } \prod_{l}\frac{\partial F_l}{\partial x_l}, \qquad \text{residual: } \prod_{l}\Big(I + \frac{\partial F_l}{\partial x_l}\Big). \]

\(I\) is the identity matrix (the slope of “do nothing”). For scalars with small branch slopes \(f_l = 0.01\) over 50 blocks: plain \(0.01^{50} = 10^{-100}\), residual \(1.01^{50} \approx 1.64\). Ignoring the ReLU after each addition, expanding the product also shows the gradient at the top reaches every block directly, through the “1” terms. This derivation is not in the paper; the same authors made it the centrepiece of their follow-up, “Identity Mappings in Deep Residual Networks” (He et al., 2016), which moved the ReLU off the shortcut path so the identity is exact.

⚠ Careful: this is not the paper’s argument

The paper’s networks have batch normalization, and it states that its plain networks do not suffer from vanishing gradients (Chapter 16). So “shortcuts fix vanishing gradients” is not why ResNets beat plain nets in the paper; the paper’s own explanation is that residual learning makes optimization easier (preconditioning, Chapter 19). The widget shows a real but separate benefit, visible when normalization is absent.

Residual learning

When shapes change: Eq. (2) and options A, B, C

Where a block halves the map and doubles the channels, the shortcut must be zero-padded or projected to match.

Eq. (1) adds \(x\) to \(F(x)\), so they must have the same shape. At the first block of each new stage, \(F\) starts with a stride-2 convolution and doubles the channels (e.g. 64 × 56 × 56 → 128 × 28 × 28). The paper gives two ways to make the shortcut fit. Option A: keep the identity, take every second position (stride 2), and pad the extra channels with zeros; no parameters. Option B: use a projection shortcut, a 1×1 convolution with stride 2, only where shapes change. A third variant, option C, uses projections on every shortcut.

∑ The math (paper Eq. 2, §3.2)
\[ y = \mathcal{F}(x, \{W_i\}) + W_s\, x. \qquad\text{(2)} \]

\(W_s\) is a linear projection: for convolutional maps, a 1×1 convolution (followed by BN in the official models) from \(C_{\text{in}}\) to \(C_{\text{out}}\) channels with stride 2, so \(C_{\text{in}} C_{\text{out}}\) weights. For conv3_1 of ResNet-34: \(64 \times 128 = 8{,}192\) weights. A square \(W_s\) could be used on every block too, but “identity mapping is sufficient for addressing the degradation problem and is economical, and thus \(W_s\) is only used when matching dimensions”.

📄 In the paper

“(A) The shortcut still performs identity mapping, with extra zero entries padded for increasing dimensions. This option introduces no extra parameter; (B) The projection shortcut in Eqn.(2) is used to match dimensions (done by 1×1 convolutions). For both options, when the shortcuts go across feature maps of two sizes, they are performed with a stride of 2” Paper §3.3. Option C (“all shortcuts are projections”) is introduced with the Table 3 comparison §4.1; in Fig. 3 the dimension-increasing shortcuts are drawn dotted.

⌨ In the code

The official ResNet-50/101/152 use option B: a branch1 projection (1×1, stride 2 from stage 3 on) only in the first block of each stage (res3a_branch1, L488–500). torchvision adds downsample = conv1x1(…, stride) + BN whenever the stride or the channel count changes (resnet.py L239–243), i.e. option B for every depth, including ResNet-18/34 (the paper’s Table 2 used option A for those). This book’s RNT.padShortcut implements option A.

Residual learning

The unrolled view: many paths

Expand the additions and a residual network looks like a collection of many shorter networks sharing weights.

Each block offers two routes: through \(F\) or around it. Follow a signal from input to output and choose a route at every block: with \(n\) blocks there are \(2^n\) different paths, most of them of medium length. This picture, from later work, helps explain why removing a single block from a trained ResNet hurts it much less than removing a layer from a plain network:

∑ The math (later work, ignoring the ReLU after each addition)
\[ x_2 = x_0 + F_1(x_0) + F_2\big(x_0 + F_1(x_0)\big), \] \[ \#\{\text{paths through } k \text{ of } n \text{ blocks}\} = \binom{n}{k}, \qquad \sum_{k=0}^{n} \binom{n}{k} = 2^n. \]

\(x_l\) is the signal after block \(l\). Already two blocks give 4 routes: skip both (\(x_0\)), only \(F_1\), only \(F_2\), or both. \(\binom{n}{k}\) (“n choose k”) counts the ways to pick which \(k\) blocks a path goes through; it peaks at \(k = n/2\).

⚠ Not in the paper

This view is from Veit, Wilber & Belongie, “Residual Networks Behave Like Ensembles of Relatively Shallow Networks” (NeurIPS 2016). The paper itself only says that with identity shortcuts “all information is always passed through, with additional residual functions to be learned” (§2). Because ResNet’s ReLU sits after each addition, the expansion is exact only where the sums are positive.

Residual learning

Relatives: residual representations and highway networks

Residuals were known to make problems easier elsewhere; gated shortcuts appeared at the same time, but can close.

The paper places its idea among older ones. Residual representations in image retrieval (VLAD, Fisher vectors) encode an image by its differences from a dictionary, and encoding residual vectors works better than encoding the vectors themselves in vector quantization. In numerical methods, multigrid solvers and hierarchical basis preconditioning work with residuals between coarse and fine scales, and converge much faster than solvers unaware of this. Lesson: a good reformulation can make optimization easier.

Shortcut connections are older still: early multi-layer perceptrons added a linear layer straight from input to output; GoogLeNet attached extra classifiers to middle layers. The closest relative, published concurrently, is the highway network (Srivastava, Greff & Schmidhuber, 2015), whose shortcuts are controlled by learned gates:

∑ The math (highway networks, as described in §2)
\[ \text{highway: } y = H(x)\cdot T(x) + x\cdot\big(1 - T(x)\big), \qquad T(x) = \sigma_{\text{sig}}(W_T x + b_T); \] \[ \text{residual: } y = F(x) + x. \]

\(T(x)\) is the transform gate, a sigmoid (between 0 and 1) with its own weights \(W_T\) and bias \(b_T\); \(\cdot\) multiplies entry by entry. When \(T \to 1\) the shortcut is “closed” and the layer computes a non-residual function \(H(x)\); when \(T \to 0\) it passes \(x\). The residual block is the gate-free special case where the identity is always fully open.

📄 In the paper

“These gates are data-dependent and have parameters, in contrast to our identity shortcuts that are parameter-free. When a gated shortcut is ‘closed’ (approaching zero), the layers in highway networks represent non-residual functions. On the contrary, our formulation always learns residual functions; our identity shortcuts are never closed … In addition, highway networks have not demonstrated accuracy gains with extremely increased depth (e.g., over 100 layers)” Paper §2. Highway nets appear in Table 6: 19 layers, 7.54%; 32 layers, 8.80% (Chapter 34).

The ResNet architectures

Plain-34 and ResNet-34 (Fig. 3)

The residual network is the plain network plus a shortcut around every pair of 3×3 layers, at almost no extra cost.

To test residual learning fairly, the paper builds a plain network and its residual counterpart that differ only in the shortcuts. The plain 34-layer net follows VGG’s philosophy: a 7×7 stride-2 convolution with 64 filters, a 3×3 max pool, then four stages of 3×3 convolutions with 64, 128, 256 and 512 filters on 56, 28, 14 and 7-pixel maps (3, 4, 6 and 3 pairs of layers), global average pooling and a 1000-way fully-connected layer. The residual version adds a shortcut around each pair: 16 shortcuts, 3 of them dimension-increasing.

∑ The math
\[ \text{depth} = 1\ (\text{conv1}) + 2\,(3 + 4 + 6 + 3)\ (\text{3×3 layers}) + 1\ (\text{fc}) = 34. \]

The FLOPs are the sum of Chapter 14’s formula over these layers. The 16 additions of ResNet-34 cost \(\sum H W C\) additions in total (about 1.4 million), negligible next to 3.6 billion multiply-adds.

📄 In the paper

“Based on the above plain network, we insert shortcut connections (Fig. 3, right) which turn the network into its counterpart residual version” Paper §3.3, Fig. 3. VGG-19: 19.6 billion FLOPs; the 34-layer plain and residual networks: 3.6 billion each.

⌨ In the code

torchvision: resnet34 = _resnet(BasicBlock, [3, 4, 6, 3], …) (resnet.py L710–731), with the stem conv1, bn1, relu, maxpool and stages layer1…layer4 (L197–206).

The ResNet architectures

The bottleneck block (Fig. 5)

For deeper nets, each block squeezes the channels with a 1×1, does the 3×3 work on the thin version, and widens again.

Going beyond 34 layers with basic blocks gets expensive. The bottleneck block uses three layers instead of two: a 1×1 convolution that reduces, say, 256 channels to 64; a 3×3 convolution on those 64; and a 1×1 that restores 256. The narrow middle is the “bottleneck”. A bottleneck block on 256-d maps costs about the same as a basic block on 64-d maps, but has three layers and works with 4× wider maps between blocks:

∑ The math
\[ \text{basic (64-d): } 2\cdot 3^2\cdot 64\cdot 64 = 73{,}728, \qquad \text{bottleneck (256-d): } 256\cdot 64 + 3^2\cdot 64\cdot 64 + 64\cdot 256 = 69{,}632. \]

Weights per block (without BN); multiply by \(56^2\) for multiply-adds. A projection shortcut on the bottleneck would add \(256 \times 256 = 65{,}536\) weights: almost doubling the block, because it connects the two wide ends. Hence identity shortcuts everywhere except the first block of each stage.

📄 In the paper

“Because of concerns on the training time that we can afford, we modify the building block as a bottleneck design. For each residual function \(\mathcal{F}\), we use a stack of 3 layers instead of 2 … the 1×1 layers are responsible for reducing and then increasing (restoring) dimensions, leaving the 3×3 layer a bottleneck with smaller input/output dimensions” Paper §4.1, Fig. 5. “If the identity shortcut in Fig. 5 (right) is replaced with projection, one can show that the time complexity and model size are doubled.” Footnote 4: deeper non-bottleneck ResNets also gain from depth (on CIFAR-10) but are less economical, and “the degradation problem of plain nets is also witnessed for the bottleneck designs”.

⌨ In the code

torchvision’s Bottleneck (resnet.py L108–163): expansion = 4; conv1 (1×1) → conv2 (3×3) → conv3 (1×1 to 4 × planes), each with BN, ReLU after the first two and after the addition. Its comment (L109–113) notes one deliberate change: it puts the stride-2 on the 3×3 (“ResNet V1.5”), while the paper’s models put it on the first 1×1 (Chapter 29).

The evidence

Measuring image classifiers

ImageNet results are reported as top-1 and top-5 error, on validation or test images, from one crop, ten crops or many scales.

Top-1 error is the fraction of images whose most likely predicted class is wrong. Top-5 error counts an image as correct if the true class is anywhere among the five most likely; ImageNet’s 1,000 classes include near-duplicates (dozens of dog breeds), so top-5 was the competition’s headline metric. An ensemble averages the predictions of several separately trained networks.

∑ The math
\[ \text{top-}k\text{ error} = \frac{1}{N}\sum_{n=1}^{N} \mathbf{1}\big[\, y_n \notin \text{top}_k(p_n) \,\big]. \]

\(N\) images, \(y_n\) the true class of image \(n\), \(p_n\) its predicted probabilities, \(\text{top}_k\) the \(k\) most likely classes, and \(\mathbf{1}[\cdot]\) is 1 when the condition holds, 0 otherwise. A “relative improvement” compares errors as a ratio: from 21.2 to 27.2 mAP is \(6.0/21.2 \approx 28\%\).

The models are trained on the 1.28 million training images, and evaluated on the 50k validation images. We also obtain a final result on the 100k test images, reported by the test server. We evaluate both top-1 and top-5 error rates” Paper §4.1. Tables 2 and 3 use 10-crop testing on validation; Table 4 the best single models (multi-scale); Table 5 ensembles on the test set.

The evidence

The CIFAR-10 study (Table 6, Fig. 6)

A simple family of thin networks shows the same pattern from 20 to 110 layers: plain nets degrade, ResNets improve.

To study extreme depth cheaply, the paper uses CIFAR-10 and deliberately simple networks: inputs 32×32, a first 3×3 convolution, then three stages of \(2n\) 3×3 layers on 32, 16 and 8-pixel maps with 16, 32 and 64 filters, global average pooling, a 10-way layer. Residual versions put a shortcut around every pair of layers (\(3n\) shortcuts, all option A), so plain and residual nets have exactly the same parameters.

∑ The math
\[ \text{depth} = 6n + 2, \qquad \text{params}(n) = \underbrace{3\cdot 9\cdot 16}_{\text{first conv}} + \sum_{\text{3×3 layers}} 9\, C_{\text{in}} C_{\text{out}} + \underbrace{2\sum C}_{\text{BN } \gamma, \beta} + \underbrace{64\cdot 10 + 10}_{\text{fc}}. \]

\(n = 3, 5, 7, 9\) give 20, 32, 44, 56 layers; \(n = 18\) gives 110; \(n = 200\) gives 1202. This book’s count for \(n = 3\) is 269,722 ≈ 0.27M, matching Table 6, and likewise 0.46M, 0.66M, 0.85M, 1.7M and 19.4M.

The evidence

Layer responses (Fig. 7)

Residual layers respond more weakly than plain layers, and more weakly still in deeper ResNets: each makes a small correction.

If residual functions are “closer to zero” (Chapter 19), the layers inside the residual branches should produce small outputs. The paper measures the standard deviation of each 3×3 layer’s response, after BN and before the ReLU or the addition, on CIFAR-10. In ResNets this is the strength of the residual function itself. The same measurement on the toy networks:

∑ The math
\[ s_l = \sqrt{\frac{1}{M}\sum_{m=1}^{M} \big(r_{l,m} - \bar r_l\big)^2}. \]

\(r_{l,m}\) are the \(M\) numbers in layer \(l\)’s response (all images, channels and positions), \(\bar r_l\) their mean. Because each response comes straight out of BN, its scale is set mostly by the learned \(\gamma\): a small \(s_l\) means the network chose to turn that layer’s contribution down.

📄 In the paper

“Fig. 7 shows that ResNets have generally smaller responses than their plain counterparts. These results support our basic motivation (Sec.3.1) that the residual functions might be generally closer to zero than the non-residual functions. We also notice that the deeper ResNet has smaller magnitudes of responses, as evidenced by the comparisons among ResNet-20, 56, and 110 in Fig. 7. When there are more layers, an individual layer of ResNets tends to modify the signal less” Paper §4.2, Fig. 7. Read off Fig. 7 (≈): plain-56 mostly between 1 and 2.3; ResNet-56 around 1; ResNet-110 mostly around 0.8–1.

The evidence

Beyond classification: object detection

Swapping VGG-16 for ResNet-101 inside the same detector improves COCO results by 28% relative.

Object detection asks for every object in an image: a class and a bounding box. A predicted box counts if its intersection over union (IoU) with a true box is high enough. Average precision (AP) summarizes how precise the detections are as more of the objects are found; mAP averages it over classes. PASCAL VOC uses an IoU threshold of 0.5 (mAP@.5); COCO’s main metric, mAP@[.5, .95], averages over the thresholds 0.5, 0.55, …, 0.95, rewarding precise boxes.

The detector is Faster R-CNN (Ren, He, Girshick & Sun, 2015): a backbone network computes feature maps, a region proposal network suggests about 300 candidate boxes, and a head classifies and refines each. ResNet-101 replaces VGG-16 as the backbone: conv1 to conv4_x are shared (91 convolutional layers), regions are pooled before conv5_1, and conv5_x serves as the per-region head; BN statistics are frozen (arXiv appendix A).

∑ The math
\[ \text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A\cap B|}{|A| + |B| - |A\cap B|}, \] \[ \text{mAP@}[.5, .95] = \frac{1}{10}\sum_{t \in \{0.5,\, 0.55,\, \dots,\, 0.95\}} \text{mAP@}t. \]

\(|A|\) is a box’s area. Two 10×10 boxes overlapping in a 5×10 strip: IoU \(= 50/(100 + 100 - 50) = 1/3\): a miss even at 0.5.

📄 In the paper

Table 7 (VOC): VGG-16 73.2 / 70.4, ResNet-101 76.4 / 73.8 (VOC 2007 / 2012 test). Table 8 (COCO val): mAP@.5 41.5 → 48.4, mAP@[.5,.95] 21.2 → 27.2. “The detection implementation of using both models is the same, so the gains can only be attributed to better networks … we obtain a 6.0% increase in COCO’s standard metric (mAP@[.5, .95]), which is a 28% relative improvement” Paper §4.3. The appendix (arXiv v1 only) adds box refinement, global context and multi-scale testing (COCO test-dev 55.7 / 34.9 single model, 59.0 / 37.4 ensemble), VOC 85.6 / 83.8, ImageNet detection 62.1 mAP (ensemble, 1st place, 8.5 points ahead of the runner-up) and ImageNet localization 9.0% top-5 error (1st place) arXiv Appendix A–C, Tables 9–14.

Limits and where this leads

The paper leaves open why plain nets degrade and how to regularize huge ResNets; its shortcut became part of almost every later network.

What the paper leaves open. It does not explain why deep plain networks are hard to optimize, only conjectures “exponentially low convergence rates”. The preconditioning argument is a hypothesis supported by Fig. 7, not a proof. The 1202-layer network overfits, and the remedy (stronger regularization) is left for later. Footnote 2 notes that even the premise that stacked nonlinear layers can approximate complicated functions is “still an open question”.

What came next. The same authors’ Identity Mappings in Deep Residual Networks (2016) moved BN and ReLU before the weights (“pre-activation”), making the shortcut a pure identity, and trained a 1001-layer CIFAR network to 4.62% error (the code linked from the official README). Wide ResNets (Zagoruyko & Komodakis, 2016) traded depth for width; ResNeXt (Xie et al., 2017) split the bottleneck into groups; DenseNet (Huang et al., 2017) concatenated instead of adding. And the shortcut left vision: every Transformer layer computes \(x + \text{Sublayer}(x)\).

💡 The one-sentence summary

Making “do nothing” the default for every few layers turns very deep networks from hard to optimize into easy to optimize, at the cost of one addition per block.

📄 In the paper

The paper ends its introduction expecting that the residual learning principle “is applicable in other vision and non-vision problems” Paper §1. In this collection, residual connections return in the Transformer (lesson 8), BERT, GPT-3, the Vision Transformer, whose image classifier competes with ResNets, and diffusion models, whose U-Nets are built from residual blocks. Glossary

10-crop testing
Classifying the four corner crops, the centre crop and their mirror images, and averaging the ten predictions.
Average precision (AP), mAP
A detection score summarizing precision as more objects are found; mAP averages it over classes (and, for COCO, over IoU thresholds 0.5–0.95).
Basic block
The two-layer residual block of ResNet-18/34: 3×3 conv, BN, ReLU, 3×3 conv, BN, add the shortcut, ReLU.
Batch normalization (BN)
Standardizing each channel with its minibatch mean and variance, then scaling by γ and shifting by β (Ioffe & Szegedy, 2015).
Bottleneck block
The three-layer residual block of ResNet-50/101/152: 1×1 (reduce), 3×3, 1×1 (restore).
Bounding box
The rectangle a detector draws around an object.
Building block
The paper’s name for a few layers with a shortcut around them (Fig. 2).
Channel
One of the grids of a picture or of a layer’s output (red, green, blue; or one feature map).
CIFAR-10
A data set of 60,000 colour photos of 32 × 32 pixels in 10 classes (50,000 for training, 10,000 for testing).
Convolutional layer
A layer that slides small learned filters over its input, computing the same weighted sum at every position.
Convolutional neural network (CNN)
A network built mainly from convolutional layers.
Degradation problem
Adding layers to a deep plain network raising its training error, not only its test error.
Depth
The number of layers with weights.
Downsampling
Shrinking feature maps, in ResNet by stride-2 convolutions (and one max pool).
Element-wise addition
Adding two equally shaped blocks of numbers entry by entry.
Ensemble
Several separately trained models whose predictions are averaged.
Exploding gradient
A gradient that grows layer after layer during backpropagation.
Fan-in
The number of inputs summed by one neuron; k²·Cin for a convolution.
Faster R-CNN
The object detector used in §4.3: a backbone network, a region proposal network and a per-region classifier.
Feature map
One channel of a layer’s output: a grid saying where a feature was found.
Filter (kernel)
The small table of weights a convolution slides over its input.
FLOPs
In this paper, the number of multiply-adds needed to process one image.
Global average pooling
Averaging each whole feature map into one number per channel.
He initialization
Random starting weights with variance 2/fan-in, which keeps signals the same size through ReLU layers.
Highway network
A concurrent architecture whose shortcuts are controlled by learned, data-dependent gates (Srivastava et al., 2015).
Identity mapping
A function that returns its input unchanged.
ImageNet (ILSVRC)
The image-classification benchmark with 1.28 million training photos in 1,000 classes, 50,000 validation and 100,000 test photos.
Intersection over union (IoU)
The overlap area of two boxes divided by the area they cover together.
Jacobian
The table of slopes of every output of a layer with respect to every input.
Max pooling
Keeping the largest value in each window.
Minibatch
The small random group of examples used for one SGD step.
Momentum
An SGD variant that keeps a running velocity of past gradients (μ = 0.9 in the paper).
Multi-scale testing
Running the network on the image resized to several sizes and averaging the scores.
Option A / B / C
Shortcuts at dimension changes: A zero-pads the identity, B projects only there, C projects every shortcut.
Padding
Zeros added around an input so the kernel can be centred on border pixels.
Per-pixel mean
The average training image, subtracted from every input.
Plain network
A network of stacked layers without shortcuts; the paper’s baseline.
Pooling
Summarizing each neighbourhood of a feature map by its maximum or average.
Preconditioning
Reformulating a problem so that a solver starts closer to the solution.
Projection shortcut
A shortcut with a 1×1 convolution Ws that changes the number of channels (Eq. 2).
Receptive field
The patch of the input that can influence one output of a layer.
Residual function
F(x) = H(x) − x: what the layers of a residual block learn.
Residual network (ResNet)
A network built from building blocks with shortcut connections.
Scale augmentation
Resizing training images to a random size (shorter side in [256, 480]) before cropping.
Shortcut connection
A connection that skips one or more layers; in ResNet it carries the input to be added to the layers’ output.
Stage
A group of blocks working on the same feature-map size (conv2_x … conv5_x).
Stride
How many pixels a kernel moves between positions; stride 2 halves the map.
Top-1 / top-5 error
The fraction of images whose true class is not the first guess / not among the five best guesses.
Underfitting
A model that cannot fit even its training data.
Validation set
Held-out examples used to measure a model during development.
Vanishing gradient
A gradient that shrinks layer after layer during backpropagation until lower layers barely learn.
VGG
The 16- and 19-layer networks of 3×3 convolutions (Simonyan & Zisserman, 2015) that inspired the plain baselines.
Warm-up
Training with a small learning rate for a short time before switching to the normal one.
Weight decay
A small pull of every weight towards zero added to the gradient (λ = 0.0001 in the paper).
Weight sharing
Using the same kernel weights at every position of a convolution.
